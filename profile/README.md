<p>这篇以家用或小型办公路由器为对象，讲双ISP双线路怎么设：先确认路由器是否支持双WAN，再讲接线与拨号、负载均衡和策略路由的取舍、故障切换参数，最后给验证与排错步骤。</p>
<h2>一、先看路由器支不支持双WAN</h2>
<p>很多家用路由只有一个WAN口，插两条线也用不上，选设备前先看接口和固件功能。</p>
<p>支持双WAN的机型，通常能在管理页里看到负载均衡和故障转移两个开关。</p>
<p>软路由的自由度更高，但需要自己配规则，适合愿意折腾的人。</p>
<p>路由器位置也要考虑，两条外线最好从同一处进户，拉到两个房间会让走线变得很难看。</p>

<h2>二、接线和拨号怎么弄</h2>
<p>两条外线分别接WAN1和WAN2，光猫建议桥接，由路由器分别拨号。</p>
<p>两条线都用路由模式也能用，但会出现双重NAT，端口映射和排错都会变复杂。</p>
<p>拨号成功后先单独测每条线，确认都能上网，再开双WAN功能。</p>
<h3>一条线拨号一条线自动获取也能用</h3>
<p>混用不影响基本功能，但故障切换的判断会不准，建议两条线尽量用同一种接入方式。</p>
<h3>先给两条线打标签</h3>
<p>在管理页把两条线分别命名，比如主线和备线，后面写规则时不容易选错接口。</p>
<p>标签顺手记下带宽和运营商，出故障时看一眼就知道该找谁，省掉翻合同的步骤。</p>
<h2>三、负载均衡还是策略路由</h2>
<p>负载均衡按连接分摊，配置简单，适合纯浏览，问题是同一账号的出口会跳。</p>
<p>策略路由按规则指定出口，稳定可预期，多账号场景应该选这个。</p>
<p>两者可以叠加，关键业务走策略，其余流量走负载均衡，兼顾稳定和利用率。</p>
<p>策略路由的规则不要写太细，目标地址一多，路由表会变得难以维护，也容易漏项。</p>

<h2>四、故障切换怎么设</h2>
<h3>探测目标要选稳的</h3>
<p>探测目标选稳定的公网地址，别用容易被限速的域名，否则误判会很频繁。</p>
<p>探测间隔十秒到三十秒，连续失败三次再切，能避开瞬时抖动。</p>
<p>切回要加延迟，线路刚恢复就切回去，容易在两条线之间反复横跳。</p>
<h2>五、配置完怎么验证</h2>
<p>先看路由器的线路状态页，两条线都应为已连接，带宽和延迟显示正常。</p>
<p>再从内网设备查出口地址，确认按规则落到了预期的那条线。</p>
<p>最后拔掉一条线，观察切换时间和业务是否中断，记录实际秒数。</p>
<p>再连续跑一天，看日志里有没有反复切换的记录，频繁切换往往说明探测目标选得不对。</p>
<h2>六、常见问题排查</h2>
<p>两条线都通但网速没提升，多半是负载均衡按目标地址哈希，单个大流量走不到两条线。</p>
<p>部分网站打不开，检查MTU和DNS，双WAN下DNS没分流会导致解析绕远。</p>
<p>切换后断流，看会话是否被清除，部分路由器切换时会重置全部连接。</p>
<p>还有一类是内网回环，策略规则把内网网段也匹配进去，局域网互访会直接断掉。</p>
<h2>常见问答</h2>
<h3>家用路由器能直接插两条宽带吗？</h3>
<p>答：要看有没有第二个WAN口。只有一个WAN口的机型，即使插上第二条线也无法参与分流，需要换设备或加软路由。</p>
<h3>双WAN会不会让网速翻倍？</h3>
<p>答：不会。单条连接只能走一条线，只有多连接并发时才可能叠加，实际提升取决于业务类型。</p>
<h3>策略路由配好后还能改吗？</h3>
<p>答：可以，规则是热生效的，改完观察一会儿即可。建议改前备份配置，避免规则写错后无法回退。</p>
<h3>两条线带宽不一样怎么分？</h3>
<p>答：按带宽比例分配非关键流量，关键业务绑到质量更好的那条，不必追求完全均衡。</p>
